### 为什么训练好、生成差？

- **训练数据形态问题**：ground_truth 本身是文档碎片（“6.3.10 索赔单状态维护 …”），不是自然问答。模型学会了“复述文档片段”，但片段与问题不强对应——评测时拿域内文档片段去比另一个文档片段，自然 overlap 低。
- **问题泛化不足**：测试问题高度重复（“索赔流程是怎样的？”出现 11 次），但每个 ground_truth 对应不同文档节选，模型无法通过问题区分该返哪一片。
- **Thinking 与截断**：Qwen3 思考模式挤占 token，之前的 inference 显示 <think> 空思考 + 片段化回答；温度/模板不匹配进一步拉低。

> 这正是课程笔记里“案例2：提示词问题”——检索/训练分数不低，但 answer_correctness 低，根因是**回答风格与参考答案不匹配 + 文档碎片化**。

## 3. Bad Case 模式（按 inference 11题 + 80抽样）

| 模式 | 例子 | 占比 |
|------|------|------|
| 表格碎片直接输出 | “发动机 20万公里 … 动力胶元 6万公里” | ~15% |
| 文档页眉/目录 | “共17页，第X页”“申请编号1034229344” | ~10% |
| 答非所问（取错片段） | 问P0562答“延保流程”、问首保答“客户档案管理” | **~70%** |
| 相对好的 | T5/T3参数、空调不制冷（条列步骤） | ~5% |

**阈值**：bad = correctness<0.5 或含 junk 模式（页码、申请编号、URL 等）——与课程笔记的 bad_case_threshold=0.5 一致。

## 4. 数据质量复盘

- v2 已过滤 8.8% 垃圾（__XLSX_ERROR__、URL、工号/审批单等）
- 但剩余数据仍是**摘录式**，非**问答式**：需要进一步做“问答重写”——把“文档节选”用 LLM 改写为自然问答对（类似 RAG 的 Gold Set 构建）。
- 建议下一轮：对 2891 条做 LLM 改写 + 人工抽检 100 条，形成真正的 Golden Set，再训 v3。

## 6. 回归建议（对应笔记 7步闭环的“改进→回归”）

1. **短期（Hybrid 兜底）**：用域内模型做“主”，联网通用模型做“辅”融合（已实现 `serve_hybrid.py` @8101），对 bad case 有明显可读性提升（见 hybrid 验证）。
2. **中期（数据重构）**：用 Qwen-Max 对 2891 条做“文档→问答”重写，人工校验后训 v3，预期 correctness 从 0.06 → 0.4+。
3. **长期（RAG 化）**：把 CRM 文档接入向量检索，微调模型只负责“生成风格”，事实由检索提供，评估切回标准 RAGAS 5 指标。
