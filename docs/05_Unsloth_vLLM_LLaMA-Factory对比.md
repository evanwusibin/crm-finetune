# Unsloth / vLLM / LLaMA-Factory 对比

> **日期**：2026-06-25
> **背景**：训练阶段是否需要这些工具？推理阶段呢？

---

## 一、三个工具对比

| 工具 | 是什么 | 用于什么阶段 | 学习阶段需要吗 |
|---|---|---|---|
| **Unsloth** | 训练加速库（2-5x 快，省 60% 显存） | 训练阶段 | ❌ 不需要，TRL+PEFT 够用 |
| **vLLM** | 高性能推理引擎（高并发、低延迟） | 部署推理阶段 | ❌ 不需要，transformers 够用 |
| **LLaMA-Factory** | 一站式微调框架（Web UI、多模型支持） | 训练阶段 | ❌ 不需要，你在学原理 |

---

## 二、详细对比

### Unsloth（训练加速）

**是什么**：通过优化 CUDA kernel 让 LoRA 训练更快更省显存

**好处**：
- 训练速度提升 2-5 倍
- 显存减少 60%
- 支持更多模型

**什么时候用**：
- 显存紧张时（比如 12GB 卡跑 8B 模型）
- 需要快速迭代时

**学习阶段不用的原因**：
- 4B 模型 12GB 卡已经够用
- TRL + PEFT 是标准方案，面试更常问
- Unsloth 是"优化"，不是"基础"

---

### vLLM（推理部署）

**是什么**：高性能推理引擎，支持 PagedAttention、连续批处理、张量并行

**好处**：
- 推理速度比 transformers 快 10-20 倍
- 支持高并发（同时处理多个请求）
- 显存利用率高（PagedAttention）

**什么时候用**：
- 生产环境部署
- 需要同时服务多个用户
- 对延迟要求高

**学习阶段不用的原因**：
- 学习阶段用 transformers 推理够了
- vLLM 是部署优化，不是训练
- 等要上线时再学

---

### LLaMA-Factory（一站式框架）

**是什么**：封装了 SFT/LoRA/QLoRA/DPO 等方法，提供 Web UI

**好处**：
- 不用写代码，点点鼠标就能训练
- 支持很多模型和方法
- 集成了评估、导出、部署

**什么时候用**：
- 不想写代码，快速验证
- 需要对比多种微调方法
- 非技术人员参与训练

**学习阶段不用的原因**：
- 你在学原理，LLaMA-Factory 是"黑盒"
- 面试会问底层细节，不能只会用工具
- 掌握原理后再用 LLaMA-Factory 效率更高

---

## 三、什么时候用这些工具

| 阶段 | 工具 | 原因 |
|---|---|---|
| **学习阶段**（现在） | TRL + PEFT + transformers | 学原理，面试常问 |
| **原型验证** | LLaMA-Factory | 快速对比不同方法 |
| **生产训练** | Unsloth + TRL | 加速训练，省显存 |
| **生产部署** | vLLM | 高并发、低延迟 |

---

## 四、整体路线图

```
现在：TRL + PEFT（学原理）
     ↓
原型：LLaMA-Factory（快速验证）
     ↓
生产训练：Unsloth + TRL（加速）
     ↓
生产部署：vLLM（高并发）
```

---

## 五、一句话总结

**先学原理，再用工具。原理学会了，工具一看就会；原理不会，工具只会点按钮。**

---

## 六、面试怎么回答

**面试官问："你用过 LLaMA-Factory 吗？"**

❌ 错误回答："我只会用它的 Web UI 点按钮"

✅ 正确回答：
"我了解 LLaMA-Factory，它是一个一站式微调框架，封装了 SFT/LoRA/QLoRA/DPO 等方法。但我更注重理解底层原理——我用 TRL + PEFT 手写过 LoRA 微调流程，理解数据格式化、量化配置、LoRA 适配器插入、训练循环、模型合并等每个环节。掌握了这些，LLaMA-Factory 一看就会。"
