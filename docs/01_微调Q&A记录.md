## 环境配置 Q&A

### Q1：为什么要单独创建 Python 环境？
**A**：因为 PyTorch CUDA 版本只支持到 Python 3.12，你的基础环境是 3.13.9，装不上 CUDA 版本。

### Q2：为什么要用 conda 而不是 venv？
**A**：conda 可以指定 Python 版本（3.12），venv 只能用系统已有的 Python。

### Q3：为什么装成了 32 位 Python？
**A**：conda 默认可能装 32 位。解决：`--subdir win-64` 强制 64 位。

### Q4：RTX 5070 Ti 的 sm_120 警告有影响吗？
**A**：不影响实际运行。RTX 5070 Ti 是 Blackwell 架构（sm_120），PyTorch 还没有完全适配，但 GPU 计算正常。

### Q5：bitsandbytes 和 torch 一起 import 会 segfault？
**A**：分开 import 没问题，同时 import 可能有内存冲突。实际训练脚本中不影响。

## 数据准备 Q&A

### Q6：prepare_data.py 做了什么？
**A**：把 CRM 项目的 JSON 数据（FAQ、维修案例、故障码）转成微调脚本能读的 JSONL messages 格式。

### Q7：企业里数据准备还需要做什么？
**A**：远不止格式转换。企业级需要：数据清洗（去重/去噪/纠错）、数据标注（人工审核）、数据增强（改写/扩展）、数据配比（各类数据比例）、数据脱敏（手机号/车牌号）。

### Q8：为什么现在不做数据清洗？
**A**：学习阶段先跑通流程。数据量小（52条）、数据质量本身不错（结构化FAQ/案例），清洗收益不大。

## 超参数 Q&A

### Q9：BATCH_SIZE 为什么是 4？
**A**：显存有限（12GB），batch 越大显存越吃。4 是安全值，OOM 时改成 2。

### Q10：GRAD_ACCUM 为什么是 8？
**A**：梯度累积 = 用时间换显存。有效 batch = 4×8 = 32，小显存模拟大 batch。

### Q11：LEARNING_RATE 为什么是 3e-4？
**A**：QLoRA 是 4bit 量化，参数变化大，需要比 LoRA（3e-5）大 10 倍的学习率。

### Q12：LORA_R 为什么是 4？
**A**：r=4 可训练参数约 0.1-0.2%，学习阶段够用且快。生产可调到 8 或 16。

### Q13：TARGET_MODULES 为什么选 q_proj 和 v_proj？
**A**：Transformer Attention 有 Q/K/V/O 四个投影层。选 Q 和 V 是效果最好、显存最少的组合。

### Q14：为什么没用 PagedAttention？
**A**：PagedAttention 是推理优化（vLLM 用），训练阶段应该用 PagedAdamW（bitsandbytes 提供的训练优化器）。

## 微调方法 Q&A

### Q15：为什么用 QLoRA 而不是全参 SFT？
**A**：全参微调 Qwen3-8B 需要 ~32GB 显存，你的卡只有 12GB。QLoRA 先压缩到 4bit（~6GB），再用 LoRA 训练少量参数（~0.2%），效果接近全参。

### Q16：LoRA 和 QLoRA 的区别？
**A**：
- LoRA：全精度模型 + LoRA 适配器，显存中等
- QLoRA：4bit 量化模型 + LoRA 适配器，显存最小

### Q17：为什么要合并模型？
**A**：LoRA 训练出来的是"适配器"（很小的权重文件），需要合并到基座模型才能正常部署和推理。

## 学习定位 Q&A

### Q18：以后是不是直接让 AI 做微调就好了？
**A**：AI 能做 80%（写代码、调参、跑训练、部署），但人的价值在剩下 20%：
- 判断用什么方案（LoRA vs QLoRA vs 全参）
- 理解为什么 loss 不下降
- 评估效果好不好
- 决定数据怎么配比
- 判断过拟合还是欠拟合

**面试体现差距**：
- 只会敲命令 → "我再跑一遍"
- 理解原理 → "loss 不下降可能是学习率太大，改成 1e-4；过拟合增加 Dropout；欠拟合增加 r 或数据量"

**结论**：AI 是工具，你是驾驶员。学的不是"怎么敲命令"，而是"出了问题怎么判断和解决"。

## 踩坑记录

### Q19：为什么 QLoRA 训练每步 5 分钟，1000 步要 88 小时？
**A**：根因是 bitsandbytes 4bit 量化不支持 RTX 5070 Ti（sm_120 Blackwell 架构），量化计算 fallback 到 CPU。

**现象**：GPU 利用率接近 0%，显存占用很少，但训练极慢。

**解决**：去掉量化，改用全精度 BF16 + LoRA。每步从 317 秒降到 5-15 秒。

**教训**：
1. 警告不能忽略（sm_120 不兼容警告）
2. 先小规模测试（5 步）再跑全量
3. 训练时监控 GPU 利用率（nvidia-smi）
4. 新架构 GPU 可能不支持量化，要有 fallback 方案

详见：`docs/03_小插曲_QLoRA性能问题.md`

### Q20：为什么 Qwen3-8B 放不进 12GB 显存？
**A**：Qwen3-8B BF16 约 16GB，12GB 卡放不下。4bit 量化可以降到 ~6GB，但 bitsandbytes 不支持 RTX 5070 Ti（sm_120）。

**解决**：换 Qwen3-0.6B 学习（~2GB），掌握后再上服务器跑 8B。

**显存计算公式**：
- BF16：显存 ≈ 参数量 × 2 字节
- 4bit：显存 ≈ 参数量 × 0.5 字节

详见：`docs/04_小插曲_模型大小选择.md`

### Q21：需要用 Unsloth/vLLM/LLaMA-Factory 吗？
**A**：学习阶段都不需要。

| 工具 | 用于什么 | 学习阶段 | 生产阶段 |
|---|---|---|---|
| Unsloth | 训练加速（2-5x） | ❌ TRL+PEFT 够用 | ✅ 省显存 |
| vLLM | 高性能推理 | ❌ transformers 够用 | ✅ 高并发 |
| LLaMA-Factory | 一站式框架 | ❌ 在学原理 | ✅ 快速验证 |

**路线**：现在 TRL+PEFT（学原理）→ 原型 LLaMA-Factory → 生产 Unsloth+vLLM

详见：`docs/05_Unsloth_vLLM_LLaMA-Factory对比.md`

### Q22：TRL、PEFT、Transformers 三者是什么关系？
**A**：

| 库 | 定位 | 一句话 |
|---|---|---|
| Transformers | HuggingFace 核心库 | 模型全家桶（加载/训练/推理） |
| PEFT | 参数高效微调 | 用最少的参数实现最好的微调效果 |
| TRL | 大模型微调专用 | SFT/DPO/PPO 训练器 |

**调用链**：你的代码 → TRL（SFTTrainer）→ Transformers（模型加载）→ PEFT（LoRA 适配器）

详见：`docs/06_TRL_PEFT_Transformers关系.md`

### Q23：AutoDL 上怎么省钱部署？
**A**：用轻量模型部署，避免在 GPU 上下载大文件。

**技巧**：
1. 本地打包模型（tar -czf）
2. 上传到 AutoDL（SCP 或文件管理）
3. 在 AutoDL 上解压使用

**省钱对比**：直接下载 30-60 分钟 vs 本地克隆 5-10 分钟

详见：`docs/10_AutoDL部署省钱技巧.md`
