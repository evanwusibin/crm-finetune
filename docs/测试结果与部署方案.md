## 三、推理质量测试（11 题）

### 测试用例设计（3 类）

```python
# A. 训练集内问题（考察记忆能力）
"发动机故障灯亮了怎么办？"
"故障码P0562是什么意思？"
"比亚迪T5的参数配置是什么？"

# B. 训练集外同类问题（考察泛化能力）
"终身质保是保哪些零部件？"
"首保和定保有什么区别？"
"故障码P0300是什么意思？"
"刹车异响是什么原因？"
"空调不制冷怎么处理？"

# C. 边界/挑战题（考察鲁棒性）
"比亚迪T3的参数是什么？"          # 训练集只有T5/T7
"我的车打不着火了怎么办？"        # 模糊问题
"你们公司还招人吗？"              # 超出业务范围
```

### 测试结果

#### ✅ 正常回答（5/11）

| 问题 | 评价 |
|------|------|
| 终身质保是保哪些零部件？ | 回答完整，结构清晰，列出 7 类覆盖部件 + 4 类排除项 |
| 首保和定保有什么区别？ | 正确区分免费首保 vs 收费定保，但被 max_tokens 截断 |
| 刹车异响是什么原因？ | 正确，格式规范（原因 + 解决方法） |
| 空调不制冷怎么处理？ | 回答专业，5 步排查流程清晰 |
| 我的车打不着火了怎么办？ | 正确，5 类排查步骤合理 |

#### ⚠️ 只输出 thinking 没有回答（5/11）

| 问题 | 原因分析 |
|------|---------|
| 发动机故障灯亮了怎么办？ | 训练集有，但 thinking 太长（256 token 全被 thinking 吃掉） |
| 故障码P0562是什么意思？ | thinking 里回答还**错了**（说 P0562=节气门，实际=系统电压低） |
| 比亚迪T5的参数配置是什么？ | 训练集有，thinking 太长导致无输出空间 |
| 故障码P0300是什么意思？ | 训练集没这个码，泛化失败，thinking 里瞎猜 |
| 比亚迪T3的参数是什么？ | 训练集只有 T5/T7，产生幻觉（编造 T3 参数） |

#### ⚠️ 超范围但尝试回答（1/11）

| 问题 | 评价 |
|------|------|
| 你们公司还招人吗？ | 越界了，应该拒答，但它在"帮忙招人" |

### 问题根因与改进方向

| 问题 | 根因 | 改进方案 |
|------|------|---------|
| thinking 过长 | Qwen3 默认启用 thinking 模式，256 token 不够 | 增加 max_new_tokens 到 512，或关闭 thinking（`enable_thinking=False`） |
| 故障码答错 | 65 条数据太少，模型没记住所有故障码 | 扩充训练数据，覆盖更多故障码 |
| T3 幻觉 | 训练集只有 T5/T7，模型不知道边界 | 训练数据加"我不知道"类样本，教会模型拒答 |
| 超范围回答 | 没有教模型拒绝非业务问题 | system prompt 加限制，或训练数据加拒答样本 |

## 四、面试话术

### 30 秒版本

> "我基于真实汽车售后场景，用 Qwen3-4B + QLoRA 在 65 条数据上做了领域微调。训练后 Loss 从 3.99 降到 1.34，token 准确率从 58.5% 提升到 68.5%。在 RTX 5070 上实现 50ms 首 token 延迟、22 tok/s 吞吐。然后把微调模型接入我的 RAG 项目，替代云端 API，实现了私有化部署。"

### 面试官追问准备

| 方向 | 问题 | 回答要点 |
|------|------|---------|
| **数据** | "65 条数据够吗？" | 数据来自真实 CRM 工单 + 维修手册，按 5 类场景结构化。少量数据用 LoRA 正合适 |
| **微调方法** | "为什么选 LoRA？" | 4B 全量微调需 40GB+ 显存，LoRA 只需 12GB，单卡 5070 就能跑 |
| **评估** | "68.5% 准确率怎么算的？" | token 级别对比 ground truth + 11 题人工评测（训练内/泛化/边界三类） |
| **部署** | "怎么上线的？" | vLLM 部署合并模型，暴露 OpenAI 兼容 API，RAG 改一行配置切换 |
| **和 RAG 的关系** | "微调和 RAG 什么关系？" | RAG 解决"查什么"（检索），微调模型解决"怎么说"（生成） |

### 项目串联话术

> "我做了两个项目：一个是 RAG 知识库系统，用 Milvus 做向量检索、LangGraph 编排 6 路召回；另一个是大模型微调，用 QLoRA 在 Qwen3-4B 上训练了汽车售后领域数据。最后把两个项目打通——vLLM 部署微调模型，RAG 项目改一行配置就切换到了本地模型，实现了从检索到生成的全链路私有化。"

## 六、部署方案：微调模型接入 RAG 项目

### 整体架构

```
用户提问
    ↓
RAG Pipeline（LangGraph）
    ├─ 意图识别 → LLM（微调模型）
    ├─ 实体提取 → LLM（微调模型）
    ├─ HyDE 扩展 → LLM（微调模型）
    ├─ Milvus 检索 → BGE-M3 向量搜索
    ├─ RRF 融合 + Rerank
    └─ 生成回答 → LLM（微调模型）← 6 个调用点全换
    ↓
返回用户
```

### 第一步：vLLM 部署微调模型

```bash
# 安装 vLLM
pip install vllm

# 启动服务（把合并后的模型暴露为 OpenAI 兼容 API）
vllm serve D:/heimaAI/PytorchSDXX/10_微调/crm-finetune/model/Qwen3-4B-merged \
  --host 0.0.0.0 \
  --port 8100 \
  --served-model-name qwen3-crm \
  --max-model-len 2048
```

跑起来后就有 `http://localhost:8100/v1` 的 OpenAI 兼容 API。

### 第二步：改 RAG 项目的 .env

```bash
# 原来（小米 MiMo API）
OPENAI_BASE_URL=https://token-plan-cn.xiaomimimo.com/v1
OPENAI_API_KEY=tp-c6uajm09kmtf...
LLM_DEFAULT_MODEL=mimo-v2.5-pro

# 改成（本地微调模型）
OPENAI_BASE_URL=http://localhost:8100/v1
OPENAI_API_KEY=not-needed          # 本地部署不需要真实 key
LLM_DEFAULT_MODEL=qwen3-crm        # vLLM 的 served-model-name
```

RAG 项目的 6 个 LLM 调用点全部自动切换：
- 意图识别（`intent_recognition_service.py`）
- 实体提取（`entity_extraction_service.py`）
- HyDE 扩展（`hyde_search_sevice.py`）
- 文本压缩（`rerank_service.py`）
- 回答生成（`answer_service.py`）
- 图片摘要（`image_summary.prompt`）

### 第三步：验证

```bash
curl http://localhost:8100/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3-crm",
    "messages": [
      {"role": "system", "content": "你是比亚迪商用车智能售后助手"},
      {"role": "user", "content": "故障码P0562是什么意思？"}
    ]
  }'
```

返回格式含 `**含义**` `**可能原因**` `**建议处理**` 即切换成功。
