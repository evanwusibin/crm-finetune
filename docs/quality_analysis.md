# QLoRA 训练质量分析报告

## 1. 训练概况

| 指标 | 值 |
|---|---|
| 训练方法 | QLoRA 4bit (r=16, alpha=32) |
| 基座模型 | Qwen3-4B |
| 训练数据 | BYD_excerpt 7920 条 |
| 训练步数 | 500 steps |
| 训练耗时 | 73 分钟 |
| 最终 train loss | 1.418 |
| 最终 eval loss | 1.024 |
| Token accuracy | 77.53% |

## 2. 推理问题诊断

### 问题现象

模型输出大量重复的表格格式字符（管道符 `|`），无法生成有意义的自然语言回答。

### 根因分析

**1. 训练数据质量差**
- 原始 BYD_excerpt 文档包含大量表格格式数据（故障码表、维修记录表、车辆参数表）
- 数据预处理只是简单拼接文档内容，没有清洗噪声
- 模型学到了"表格输出"的模式，而非"问答对话"模式

**2. 序列长度不足**
- 当前 max_length=256
- 许多表格数据超过 256 tokens 被截断，导致模型学到的是不完整的模式

**3. 训练轮数不够**
- 只跑了 ~1.3 epoch
- 模型还没充分学习数据中的问答模式

**4. 数据格式问题**
- 训练数据中混合了原始文档片段和 QA 对
- 缺乏统一的对话格式校验

## 3. 优化方案

### 方案 A：数据清洗（推荐，优先级最高）

```python
# 1. 去掉原始表格格式，只保留干净的 QA 对
# 2. 过滤掉包含大量管道符的样本
# 3. 只保留问答对话格式的数据

清理规则：
- 过滤掉 | 出现次数 > 10 的样本
- 过滤掉长度 < 50 或 > 1000 的样本
- 只保留 messages 格式正确（有 system/user/assistant 角色）的样本
```

### 方案 B：增加训练配置

| 参数 | 当前值 | 建议值 |
|---|---|---|
| max_length | 256 | 512 或 1024 |
| num_train_epochs | 1.3 | 3-5 |
| gradient_accumulation_steps | 16 | 8 |
| batch_size | 16 | 32 |

### 方案 C：数据增强

- 对现有 QA 对进行改写（同义句替换、问答反转）
- 增加边界测试样本（拒答、追问）
- 增加系统指令遵循样本

## 4. 实施优先级
