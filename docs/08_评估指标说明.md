# 评估指标说明

> **日期**：2026-06-25
> **来源**：evalscope 评估框架 + 通用推理性能指标

---

## 一、训练阶段指标

| 指标 | 含义 | 好的标准 |
|---|---|---|
| **loss** | 模型预测和真实答案的差距 | 越小越好，下降趋势好 |
| **accuracy** | 预测正确的 token 比例 | 越高越好 |
| **eval_loss** | 验证集上的 loss | 比 train_loss 低说明没过拟合 |
| **grad_norm** | 梯度大小 | 稳定不爆炸就好 |
| **entropy** | 模型输出的不确定性 | 适中 |

---

## 二、推理性能指标

### TFTT（Time to First Token）

**是什么**：从发送请求到收到第一个 token 的时间

**为什么重要**：用户体验的核心指标，越快感觉越"聪明"

**好的标准**：
- < 500ms：优秀
- 500ms - 1s：良好
- 1s - 2s：一般
- \> 2s：需要优化

---

### QPS（Queries Per Second）

**是什么**：每秒能处理多少个独立查询

**为什么重要**：衡量模型的吞吐能力

**好的标准**（取决于模型大小和硬件）：
- 0.6B 模型：10-50 QPS
- 4B 模型：2-10 QPS
- 8B 模型：1-5 QPS

---

### RPS（Requests Per Second）

**是什么**：每秒能完成多少个完整请求（包括预处理和后处理）

**为什么重要**：衡量整个系统的吞吐能力

**和 QPS 的区别**：
- QPS：只算模型推理时间
- RPS：算整个请求链路（预处理 → 推理 → 后处理）

**好的标准**：通常比 QPS 低 10-30%

---

## 三、模型质量指标

### 困惑度（Perplexity）

**是什么**：模型对文本的"困惑程度"，越低表示模型越自信

**公式**：PPL = exp(loss)

**好的标准**：
- < 10：优秀
- 10-50：良好
- 50-100：一般
- \> 100：需要优化

---

### BLEU / ROUGE

**是什么**：生成文本和参考文本的相似度

**用于**：翻译、摘要等生成任务

**好的标准**：
- BLEU > 30：良好
- ROUGE-L > 40：良好

## 四、evalscope 评估框架

**是什么**：阿里开源的模型评估框架，支持多种评估指标

**支持的评估**：
- 模型质量评估（困惑度、BLEU、ROUGE）
- 推理性能评估（TFTT、QPS、RPS）
- 安全性评估（有害内容检测）
- 对比评估（多个模型对比）

**安装**：
```bash
pip install evalscope
```

**基本用法**：
```python
from evalscope import run_evaluation

# 评估模型质量
run_evaluation(
    model_path="./model/Qwen3-4B-merged",
    dataset="custom",
    metrics=["perplexity", "bleu", "rouge"]
)
```
